# anti — 任务定义前提审计

> 只读入口：编排者本地合成。不写业务代码、不派 lane、不改 Issue、不碰 `.mana/*/state.json`。
> 发现误区只报告 + 给「若重定义」草案，不自行纠正；要改转 `intake` 或 CTO 显式授权后的 Issue 编辑。
> 与 echo 的分工：echo 检「我对当前任务目标的理解是否偏移」；anti 检「那个目标本身是否被错误框定」。

## 种子反问（必答，简体中文原文）

> 在我们反复讨论过的所有问题中, 有没有一个更深层次的问题, 是我一直在绕着它走, 但一直没有真正问出口的?

## 七步骨架

1. **复述表层问题集**：用自己的话列出本次反复出现的 2–5 个问题 / 诉求（带来源：会话句 / Issue 段 / 评论）。
2. **绕行信号**：标出「换方案不换问题」「加约束回避冲突」「重复 intake 同构目标」等绕行证据；无证据写 `unknown`，不得捏造。
3. **种子反问（必答）**：显式回答种子句——有没有一个更深层次、一直绕着走却没问出口的问题？若有，**只许提出 1 个**主候选（可附 ≤2 个次选并标明「次选」）；若无，明确写「未发现更深未问问题」并说明查证范围。
4. **误区类型**（多选一或标注组合）：`wrong-goal`（目标本身错）/ `proxy-metric`（用易测指标代替真目标）/ `scope-smuggling`（把手段写成目标）/ `premature-solution`（过早锁死方案）/ `avoided-constraint`（故意不提的硬约束）/ `identity-leak`（把身份/偏好误当需求）。
5. **重定义草案**（若主候选成立）：
   - 原问题（一句话）
   - 更深问题（一句话）
   - 若按更深问题重开，建议的非目标 / 验收 / 风险路径各一行
6. **停问清单**：最多 3 个必须由 CTO 拍板的问题；不清楚处**立即停在这里**，不落实现计划、不派 lane。
7. **出口建议**：`保持原定义继续 echo/intake` | `按草案转 intake 重写 #N` | `先 /mana why 或 how 取证再回来`——三选一，附一句理由。

## 固定输出头

```
## anti 结论
- 更深未问问题: <一句 | 未发现>
- 误区类型: <标签>
- 证据: <2–5 条, 带来源>

## 表层 vs 深层
| 表层 | 深层候选 | 为何一直绕开 (推断须标 inference) |

## 若重定义
- 原问题: ...
- 更深问题: ...
- 非目标 / 验收 / 风险: ...

## 需要你拍板
1. ...
2. ...
```

## 禁止

- 空泛鸡汤、无来源断言、捏造绕行证据。
- 提出超过 1 个主候选。
- 在停问清单未答前落实现计划或派 lane。
- 自行改 Issue / 跑 `/mana run`（要改先转 `intake`）。
